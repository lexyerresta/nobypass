The contract is a file your team reviews

nobypass init reads composer.json, PSR-4 mappings, package.json and tsconfig paths, then writes a proposal. It starts from a preset and never treats the most common pattern in your code as correct.

Nothing is enforced until a person runs nobypass approve in a terminal. CI and agents cannot approve it.

controllerservicerepositorymodel

allowed_direct is about direct dependencies only. A controller reaching the model through every layer above is fine. A controller importing the model, or reaching a repository through a Laravel facade, is not.

layers:
  controller: ["app/Http/Controllers/**/*.php"]
  service:    ["app/Services/**/*.php"]
  repository: ["app/Repositories/**/*.php"]
  model:      ["app/Models/**/*.php"]
dependencies:
  allowed_direct:
    controller: [service]
    service:    [repository]
    repository: [model]
    model:      []
rules:
  direct_orm_access:
    deny_in:  [controller, service]
    allow_in: [repository]
  catch_policy:
    discourage_in: [service, repository]
    severity: warning

Seven rules, all deterministic

Each finding names the file, line, both layers, the contract edge it breaks, the approved route and a concrete fix.

RuleWhat it catchesDefault
BND001A direct dependency the contract does not allowerror
BND002Database access outside the approved layers: Eloquent, Doctrine, Prisma, TypeORM, Mongoose, Django ORM, SQLAlchemy, JPA or JDBCerror
BND003Skipping one layer, such as controller to repository when the route is controller, service, repositoryerror

CFG001A file in scope that matches no layer, or severalwarning
ANL001A file that cannot be parsed or a reference that cannot be resolved. It never passes silently.error

Nine stacks, one contract format

nobypass init detects the framework from your manifest and starts from a preset built on a documented public pattern. Every preset is a plain YAML file you can edit before approving.

From an existing repository to a required check

Node 20 or newer. Run these in the root of a Laravel, Symfony, NestJS, Express, Fastify, Next.js, Django, FastAPI or Spring Boot project. Until the npm release, install from GitHub; every npx nobypass command then runs the installed copy.

  1. npm install --save-dev github:lexyerresta/nobypass

    Adds the CLI to your devDependencies, so CI gets it from npm ci.

  2. npx nobypass init

    Writes .nobypass.proposed.yml and a discovery report. Your source files and agent instructions are not touched.

  3. npx nobypass discovery show

    Shows the detected layers, how many files each one covers, ambiguous files and every place existing code contradicts the proposal.

  4. npx nobypass approve

    Edit the proposal if needed, then approve it yourself. This writes the enforced .nobypass.yml.

  5. npx nobypass agents generate --skill

    Adds a marked block to AGENTS.md (asking first if the file exists) and writes a portable SKILL.md.

  6. npx nobypass check --since origin/main

    Fails only on violations that are new on the branch. Existing debt can go into a reviewed baseline with nobypass baseline create.

What your agents are told

Instructions can be ignored, so they are the first line, not the last.

Before you report a task as finished:
1. Run `npx nobypass check --since origin/main`.
2. If it fails, fix the violations. Move code
   to the approved layer; do not work around
   the rule.

Never edit `.nobypass.yml`, the baseline or
`exceptions:` to make the check pass.

What CI enforces

Make this a required check and protect .nobypass.yml with CODEOWNERS. SARIF output shows findings inline on the pull request.

- uses: actions/checkout@v4
  with: { fetch-depth: 0 }
- run: npm ci
- run: npx nobypass check
    --since origin/${{ github.base_ref }}
    --format sarif --output nobypass.sarif
- uses: github/codeql-action/upload-sarif@v3
  if: always()
  with: { sarif_file: nobypass.sarif }

What it does not prove

NoBypass shows that detectable violations are absent. That is narrower than "the code is correct", on purpose.

Runtime call flow
Only direct static dependencies are checked, not whether every request passes through every layer.
Untyped instance calls
$user->save() on a value whose type is not visible in the file is not detected.
Unknown code
Dynamic calls are reported as unverified, and files that fail to parse fail the check.
Governance
An agent can edit the contract locally. CODEOWNERS and branch protection are what stop that change from merging.
