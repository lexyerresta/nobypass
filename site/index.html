Your AI said it followed your architecture. Check.

NoBypass fails the pull request when generated code works but skips the layers your team approved — a query in a controller, a repository injected where only a service belongs, a catch that swallows everything.

Discover → Review → Approve → Enforce

NoBypass never decides your architecture for you. It proposes, you approve, then it holds every change to that decision.

  1. 01

    Discover

    init reads composer.json, PSR-4, package.json and tsconfig paths, starts from a preset and writes a proposal. It never treats the most common existing pattern as correct.

  2. 02

    Review

    discovery show lists the evidence: layers, coverage, ambiguous files and every place existing code contradicts the proposal.

  3. 03

    Approve

    approve is interactive only. A human signs off on .nobypass.yml; CI and agents can't.

  4. 04

    Enforce

    check --since origin/main fails only on violations new to the branch. Legacy debt goes into a reviewed baseline.

The contract is a file you can review

Layers are globs. allowed_direct lists which layer may depend on which — directly. A controller reaching the model through support, service and repository is fine. Importing it is not.

Unknown keys are rejected, exceptions need a written reason, and inline waivers exist only for the warning-level catch rule.

layers:
  controller: ["app/Http/Controllers/**/*.php"]
  support:    ["app/Support/**/*.php"]
  service:    ["app/Services/**/*.php"]
  repository: ["app/Repositories/**/*.php"]
  model:      ["app/Models/**/*.php"]
dependencies:
  allowed_direct:
    controller: [support]
    support:    [service]
    service:    [repository]
    repository: [model]
    model:      []
rules:
  direct_orm_access:
    deny_in:  [controller, support, service]
    allow_in: [repository]
  catch_policy:
    discourage_in: [service, repository]
    severity: warning

Seven rules, all deterministic

Every finding names the file, line, layers, contract edge, approved route and a concrete fix.

RuleCatchesDefault
BND001Forbidden direct dependency between layerserror
BND002Eloquent, DB::, Prisma or TypeORM access outside the approved layerserror
BND003Skipping an intermediate boundary — controller → service when the route is controller → support → serviceerror
BND004Dependency cycle between layerserror
EXC001catch where the contract discourages it, without a documented purposewarning
CFG001In-scope file that matches no layer, or severalwarning
ANL001File that couldn't be parsed or reference that couldn't be resolved — never a silent passerror

Agents get the rules. CI gets the last word.

An instruction file can be ignored. A required check can't. NoBypass does both.

nobypass agents generate --skill

Adds a delimited block to AGENTS.md (asking first if the file exists) and writes a portable SKILL.md. Works with any agent that reads AGENTS.md or Agent Skills.

Before you report a task as finished:
1. Run `npx nobypass check --since origin/main`.
2. If it fails, fix the violations (move code to
   the approved layer; don't work around the rule).

Never edit `.nobypass.yml`, the baseline or
`exceptions:` to make the check pass.

GitHub Actions + SARIF

Run it on every pull request, upload SARIF for inline annotations, make it a required check, and protect the contract with CODEOWNERS.

- uses: actions/checkout@v4
  with: { fetch-depth: 0 }
- run: npx --yes nobypass@0.1.0 check
    --since origin/${{ github.base_ref }}
    --format sarif --output nobypass.sarif
- uses: github/codeql-action/upload-sarif@v3
  if: always()
  with: { sarif_file: nobypass.sarif }

What it will not claim

NoBypass proves that detectable violations are absent. That is narrower than "your code is correct", on purpose.

  • Direct dependencies only. It doesn't prove every request walks through every layer at runtime.
  • Untyped instance calls slip through. $user->save() on a value whose type isn't visible is not detected.
  • Unknown means unknown. Dynamic calls are reported as unverified, and parse failures fail the check.
  • Governance is yours. An agent can edit the contract locally; CODEOWNERS and branch protection are what stop it.

Five minutes to the first check

Node 20 or newer. Nothing else to install.

  1. npx nobypass initWrite a proposal and a discovery report. Source files untouched.
  2. npx nobypass discovery showReview layers, coverage and contradictions.
  3. npx nobypass approveEdit the proposal if needed, then approve it yourself.
  4. npx nobypass agents generate --skillTell your agents about the contract.
  5. npx nobypass check --since origin/mainFail only on what's new.
